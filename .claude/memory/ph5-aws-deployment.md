**P22 (S3 file store) — CODE DONE 2026-08-03, branch `feat/p22-s3-file-store`.** #161 merged as `a3727a3` (branch deleted, main synced) before it started. Four findings worth keeping:
1. **DEF-015 was under-scoped — there were FOUR hardcoded buckets, not three.** `Topics/AttachFileToTopic.cs:41` carried `acmp-topics`, a bucket **no AWS environment provisions** and which the app IAM **cannot create** ⇒ topic attachment would have failed outright in cloud. 2. **★ The Minio 6.0.3 SDK IGNORES your configured AWS endpoint.** `RequestUtil.MakeTargetURL` → `S3utils.IsAmazonEndPoint` (regex `^s3[.-]?(.*?)\.amazonaws\.com$`) → replaces the host from its own `AWSS3Endpoints` map, where **us-east-1 ⇒ `s3.amazonaws.com`** (legacy global), bucket **path-style**. So `ACMP_S3_ENDPOINT=s3.us-east-1.amazonaws.com` still presigns to `https://s3.amazonaws.com/<bucket>/<key>` and **`ACMP_MEDIA_ORIGIN` must be `https://s3.amazonaws.com`** — getting it wrong blocks `<video>` playback via CSP with **nothing in the API logs**. Pinned offline by `tests/Acmp.Integration.Tests/MinioFileStoreCloudTests.cs` (presign is a local SigV4 computation once `WithRegion` is set — no AWS account needed). **That test is the U1 spike's offline half**; its live half is not duplicated in a harness — it IS the AC-078 operator check.
3. **`s3:AbortMultipartUpload` was missing from both `03-iam.sh` policies.** `PutObjectPartAsync` calls `RemoveUploadAsync` (= AbortMultipartUpload) on a part-count mismatch for **known-size streams — every upload we make**; without it that abort 403s and **masks the real part failure**. `ListParts` is never issued ⇒ `s3:ListMultipartUploadParts` deliberately left out. Edited before P20 ever ran, so it is a script edit not a live IAM change.
4. **DEVIATION (recorded, not silent):** the nginx `/acmp-recordings/` proxy is **neutralized, not deleted** — upstream moved to `set $recordings_upstream` + `resolver 127.0.0.11`, because a **literal** upstream is resolved at config load and **nginx refuses to start** when `minio` doesn't exist (the cloud stack). Deleting it outright would regress the on-prem/ngrok dev playback that `deploy/.env` (`MINIO_PUBLIC_ENDPOINT=acmp.ngrok.dev`) actually uses, and force a 2nd nginx template ahead of P25. `SL-022` objective + `PE-134` carry the deviation.
