What is being asked

WBS-26.1 is the first item of SL-035. Its row and DEC-094 d1 both say the same thing in bold: SoD-4's enforcement strength is settled before any guard is written, because a hard refusal, a warn-and-audit, and a conflict-of-interest declaration workflow are three different products. NFR-064 — created by SC-038 for this work — additionally requires that the strength of all five SoD rules be recorded, not only SoD-4's.

That is three questions, below. Every fact in this section is measured; every record it leans on is quoted verbatim beneath it.

Q1 — SoD-4's first half: decision recorder ≠ sole owner/presenter. What strength?

Option A — hard refusal, matching SoD-1 and SoD-3: audit the denied attempt, then 403. Follows C-AUTH-05's summary wording ("enforced as hard authZ checks") literally.

Option B — warn-and-audit, matching SoD-2: recording is allowed, the overlap is flagged on the decision and a distinct audit event is emitted. The pattern already exists and the catalogue already accepts it for one member.

Option C — record SoD-4 as deliberately not enforced in v1, satisfying NFR-064's strength-is-recorded clause without building a guard.

The agent's recommendation is B, and the reasoning against A is the reason the row asks at all. This committee has roughly twenty people and the Secretary drafts decisions as their ordinary job (RecordDecision's own header: "the Secretary (or Chairman) drafts a decision against a topic"). A hard recorder ≠ owner refusal would block a Secretary who also happens to own the topic from recording its decision at all — legitimate minute-taking refused by a control meant to stop self-dealing. B makes the overlap visible and reviewable without making it impossible, which is exactly the trade the catalogue already accepted for SoD-2. ⚠ This is the agent's inference, not a reading of any record: no document states which way SoD-4 should go, which is why the row was written.

⚠ Option C is offered for completeness and is not recommended, because DEC-094 d1 already ruled that the row is settled and then built.

Q2 — SoD-4's second half: COI exclusion. New evidence says this is already scoped to Phase 2.

This is the pre-interview sweep changing the question, which is the reason LL-005 says to sweep before rather than after. Measured this session across every register:

  • FR-076 already specifies the COI feature, and specifies its strength explicitly and softly: "a voter may declare a conflict; the declaration is recorded without automatically excluding the voter (exclusion is a chairman decision)". It is priority S, mvp=0, Deferred, Phase 2.
  • DW-004 — "Conflict-of-interest tracking per vote", Open, trigger Phase 2, with v1 handling recorded as "Honor system, noted in MoM".
  • WBS-9.7 already schedules it under PH-2.
  • ADR-0010's consequences name "conflict-of-interest recusals are expressible" — and a self-declared voluntary recusal already ships (RecuseVote): the current voter excludes their own ballot from quorum and tally, audited as Decisions.VoteRecused. It carries no declared reason, no conflict record and no chairman involvement, so it is a withdrawal, not a COI declaration.

So building a COI exclusion in WBS-26.1 would contradict FR-076's own words — that requirement forbids automatic exclusion — and would pull Phase-2 scope into v1 without a scope change. That is the shape trap 32 exists for: a build that reverses a settled clause nobody swept for.

Option A — confirm COI is out of v1. WBS-26.1 covers the recorder half only, and SoD-4's COI strength is recorded as "specified by FR-076, deferred to Phase 2 with DW-004; v1 handling is the honor system plus voluntary recusal".

Option B — pull FR-076 into v1. That is a scope change, not a strength choice: it needs an SC- moving FR-076 from Deferred to Approved and activating DW-004.

The agent's recommendation is A. The Phase-2 disposition is prior scoping that DEC-094 d1 did not have in front of it, and honouring it costs nothing. B is available and is yours alone.

Q3 — SoD-5 is structural, and NFR-064's strength clause is binary

NFR-064 requires each rule's strength be recorded "as either a hard refusal or a warn-and-audit". SoD-5 is neither in mechanism: it is enforced by never granting the capability, so no predicate runs and no SoD-specific code executes.

Option A — record SoD-5 as a hard refusal, on the ground that the runtime answer to an Administrator reaching committee content is a 403; "structural" describes the implementation, not the strength.

Option B — add a third category to NFR-064. That requires an SC-, because the requirement is Approved.

The agent's recommendation is A, which needs no scope change and does not weaken the requirement.

What building Q1 actually costs — read before choosing, because the row does not say this

Measured this session. SoD-4's first half needs three facts in one place, and they sit in three modules and two key spaces:

What is neededState

So this is not "add a predicate to SegregationOfDuties.cs". It is a persisted field with a migration, one widened cross-module contract, one new one, and a guard — under ADR-0001, which forbids a module reading another module's tables. That does not change the answer to Q1; it changes what the answer costs, and the row's sizing did not carry it.
