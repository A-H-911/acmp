LL-049 [lessons]

id: LL-049
title: A measurement that runs AFTER the action it should gate is a report, not a control — in a chained command the number prints, is correct, and changes nothing, and you read it only after the push has already happened.
statement: `LL-021` records that in `A && B && C` a failure in A stops the chain only for the commands that RUN. THE MIRROR IS WORSE AND FIRED HERE: A MEASUREMENT IN A CHAIN IS NOT A PREDICATE, SO IT STOPS NOTHING. Repairing a memory index that had exceeded its measured 200-line ceiling — a ceiling that exists because content past it is dropped SILENTLY — I wrote the trim, ran `wc -l`, and committed and pushed in the same `&&` chain. The count printed **202**. It was accurate, it was the exact number the whole edit existed to fix, and it was already in a pushed commit by the time I read it. **The violation I was correcting was reintroduced by the correction**, and it took two further pushes to land one trim. The fix is one construct: make the commit CONDITIONAL on the measurement — `LINES=$(wc -l < f); if [ "$LINES" -lt 200 ]; then git commit && git push; else echo OVER; fi` — at which point the same number that was a report becomes a gate.
context: 2026-09-02, close-out of the `DEF-109`/`DEC-112` session. The irony is load-bearing rather than decorative: the edit being committed was itself the repair of a limit violation, so the failure was not carelessness about the limit but a check placed downstream of the thing it was supposed to prevent. The third attempt used the conditional form and landed at 199 lines on the first try.
recommendation: Before chaining a check with an action, ask which one runs first. If the check's output is printed after the irreversible step — a commit, a push, a publish, an upsert — it is a report and must be rewritten as a predicate that can refuse. Where the action cannot be made conditional, split it into two invocations and read the number in between. ⚠ The tell is a command that ends `... && git commit && git push` with a `wc`, `grep -c`, or size check anywhere to its LEFT: the measurement has already been overtaken.
rationale: `LL-013` asks whether a check had a subject and `LL-041` whether its assertion had one; both assume the check is positioned to act. This is the prior failure: the check is correct, discriminating and about the right thing, and is simply downstream of the event it governs. It is more dangerous than a blind check because the number is RIGHT — the transcript shows the limit being measured and reported, which reads exactly like the limit being enforced, and a later reader auditing the session would see a measurement and conclude a control.
kind: improve
category: verification
impact_if_followed: A bound is enforced by the same command that could violate it, so the violating state never reaches a commit — and a limit whose breach is silent never gets a chance to be silent.
impact_if_ignored: Irreversible steps ship over known-bad measurements, and the record shows the number being observed at the moment it was ignored. Worse in a repository where the breach is invisible: nothing downstream will ever contradict it.
