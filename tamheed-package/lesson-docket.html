The lesson

THE INSTANCE. `WBS-40.8`, 2026-09-15. With axe's `color-contrast` rule switched on, the unmonitored admin tile's chip failed at 2.91:1 in English and PASSED in Arabic, on the same page with the same records. Not a violation, not 'incomplete' - absent. Counting the rule's evaluated nodes gave English 56, Arabic 25. Reading axe-core 4.13's source explained it: the rule only tests an element whose text is not an 'icon ligature', and the ligature test compares the first character drawn alone with the whole string; Arabic letters change shape when joined, so Arabic words look like ligatures, and after three hits the verdict is cached for the whole font family, taking Latin text in the Arabic font with it (`DEF-189`). Every Arabic axe pass this project ran before had `color-contrast` off, so nothing had ever shown it. The fix seeds axe's per-font cache before each run (the app has no icon fonts) and the sweep now fails by name if an Arabic page evaluates no Arabic text - and the control proved it: the Arabic admin sweeps turned red on the same chip the English ones caught.

What to do instead

(1) When a check passes in one language and fails in another on the same page, suspect the instrument before the page: count what the rule evaluated in each (passes + violations + incomplete), not only what it reported. (2) Give every per-language sweep a subject clause for that language - e.g. at least one evaluated node carrying Arabic text - so a rule that silently stops looking fails instead of passing. (3) When a scanner's heuristic is disabled or steered through internal API, make the subject clause the tripwire for a future version that stops honouring it.

Why it generalises

A scanner reports on what it chose to examine. Its skip logic is invisible in its output, so a green result in a second language can mean 'clean' or 'not looked at', and only a count of what was examined tells them apart (`LL-060`: an instrument must report on itself).

If followed

A bilingual accessibility sweep is known to have examined both languages, and a scanner upgrade that goes blind fails loudly.

If ignored

The Arabic half of an accessibility criterion is recorded Met on a pass that examined less than half the page, and contrast failures in the Arabic UI ship unseen.

LL-085 improve process Proposed

WHEN A CONTROL PASSES WHERE THE ARITHMETIC SAYS IT MUST FAIL, THE FINDING IS ABOUT THE INSTRUMENT. A RENDERED CHECK CAN READ A COLOUR MID-TRANSITION, AND AN 'INCOMPLETE' RESULT IS NOT AN EVALUATION: WAIT FOR TRANSITIONS BEFORE MEASURING, AND COUNT ONLY DECIDED RESULTS TOWARDS A SUBJECT CLAUSE.

The lesson

THE INSTANCE. `AC-173`'s control, 2026-09-15: the six formerly dimmed rules got their `opacity` back and the sweep re-ran. In the light theme every state failed; in the dark theme the impact graph's dimmed nodes - `opacity: 0.3`, computed at about 2:1 - PASSED. The agent did not accept the pass. A standalone probe of the same page a moment later measured 2.34:1 in dark, and two causes surfaced: (1) `.ig-node` transitions `opacity` over 0.15s, and the sweep ran axe the instant the class appeared, so it measured a node still fading; (2) two of the node's texts came back 'incomplete' (axe could not find their background over the graph's SVG edge layer), and the sweep's subject clause - 'the rule evaluated the formerly dimmed element' - counted incomplete as evaluated. With a wait for running CSS transitions and a subject count of passed-or-failed only, the same control failed in dark as well (1.84, 1.89).

What to do instead

(1) Before a control, write down what it must show - here a computed ratio - so a pass that contradicts the arithmetic is noticed rather than welcomed. (2) Before any rendered colour check, wait until no CSS transition is running (document.getAnimations() filtered to CSSTransition); infinite keyframe animations are a separate case. (3) In a scanner's results, treat 'incomplete' / 'needs review' as 'not determined': never let it satisfy a clause that says the element was checked.

Why it generalises

A rendered check measures the frame it is given and a scanner reports what it could decide; neither says so when it measured a transient frame or decided nothing. Only a control with a predicted outcome exposes that (`LL-060`, `LL-084`).

If followed

Contrast checks measure the resting state, and a subject clause cannot be satisfied by a result that decided nothing.

If ignored

A sweep passes on a state it caught mid-animation, or on elements it could not evaluate, and a real failure ships with a green check against it.
