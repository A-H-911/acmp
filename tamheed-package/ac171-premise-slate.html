ADR-0045 [adrs]

id: ADR-0045
title: ADR-0045: The calendar meeting chip is floored at a 24 px target box. `INV-014`'s AA clause governs its px-literal clause where the reference design cannot satisfy both — the invariant is applied, not set aside.
context: `INV-014` reads, in one statement: *"Any screen with a matching `.dc.html` matches it exactly — tokens/anatomy/states/iconography/RTL/light-dark/copy/**AA** — composed from the shared design system."* **Both the pixel literals and AA conformance are clauses of the SAME invariant.** No decision in this package had ever had to choose between them, because until now they had never disagreed.

They disagree on the calendar day-cell event chip. `features/topics/Calendar.tsx` renders each scheduled meeting as a `<button className="cal-event">`; `topics.css` styles it at `font-size: 10.5px` with `padding-block: 3px`, both taken from `ACMP Backlog & Topic.dc.html`, giving a box about **21 px** tall. WCAG 2.2 SC 2.5.8 `target-size` (Minimum) requires **24×24 CSS px** on an interactive target. `inline-size: 100%` satisfies the width; the height is short by roughly 3 px.

⚠ **THE PROJECT ADMITTED THIS CRITERION DELIBERATELY AND IN WRITING.** `rtl-a11y.spec.ts`'s tag list carries a comment: *"D-23: include WCAG 2.2 AA — the machine-testable addition over 2.1 is `target-size` (SC 2.5.8, >=24x24px)"*. The rule was not inherited by accident from a default rule set; it was chosen, named, and its cost anticipated.

⚠ **THE CONFLICT WAS INVISIBLE FOR WEEKS AND THAT IS `DEF-126`.** The e2e seed pinned every meeting to a fixed `2026-09-01`, both calendars open on the CURRENT month, so no chip ever rendered under axe and the sweep passed over an empty grid from `WBS-24.2` until the clock reached that date. The conflict is not new; only its visibility is.

⚠ A **sibling** exists: `features/meetings/MeetingsCalendar.tsx`'s `.mt-cal-event`, an `<a>` at `font-size: 9.5px` / `padding-block: 2px`, about **17 px** — worse, on a route (`/meetings`) that no accessibility sweep visited at all.
decision: d1 — **BOTH CHIPS ARE FLOORED AT A 24 px TARGET BOX AND THE TYPE IS NOT TOUCHED.** `.cal-event` gains `min-block-size: 24px` (it is already `display: flex; align-items: center`, so the content stays optically where the mock draws it and the chip grows downward by ~3 px). `.mt-cal-event` gains `min-block-size: 24px` and `line-height: 20px` — 20 + 2 + 2 = 24 exactly — keeping `display: block` because its ellipsis depends on it. **`font-size` stays 10.5 px and 9.5 px respectively: the drawn TYPE is unchanged, only the hit box grows.**

d2 — **A FLOOR, NOT MORE PADDING, AND THE DISTINCTION IS THE POINT.** Padding is derived from the type and would have to be re-derived every time the type or the inherited line-height moves; `min-block-size` states the CONFORMANCE THRESHOLD ITSELF, so it keeps holding when someone changes the font stack. A value that encodes the requirement survives edits that a value computed from the requirement does not.

d3 — **`INV-014` IS APPLIED, NOT WAIVED, AND NO NEW ADR IS OWED FOR THE NEXT CASE.** Where a `.dc.html` reference cannot satisfy both the px-literal clause and the AA clause, **the AA clause governs and the deviation is recorded**. AA is a conformance obligation the project has committed to and can fail an audit on; a px literal is a fidelity target whose own invariant already names AA beside it. ⛔ **This is deliberately NARROW: it licenses the minimum change that reaches conformance, and nothing else.** It is not a general licence to depart from a reference for taste, ergonomics or convenience — any other deviation still needs its own record.

d4 — **THE REFERENCE DESIGNS ARE NOT EDITED AND THE DIVERGENCE IS RECORDED HERE INSTEAD.** `ACMP Backlog & Topic.dc.html` and `ACMP Meetings.dc.html` are the design's source of truth and this package does not own them. A future design-parity review reading either file will find a chip whose height the implementation exceeds; **this ADR is the answer to why**, and the reason it is an ADR rather than a code comment is that a comment is invisible to that review.

d5 — **THE SWEEP MUST PROVE IT HAD A SUBJECT, NOT MERELY THAT IT RAN.** The seed becomes relative to the current month, each calendar case seeds its own meeting rather than inheriting one another spec happened to leave behind, and both cases assert a chip is VISIBLE before invoking axe. `/meetings` joins the sweep, so the sibling fix is guarded rather than merely made.
