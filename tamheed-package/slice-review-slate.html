The deferred-work row it closed — DW-072

As stored

NFR-033 IS VERIFIED ON ONE OF ITS TWO THRESHOLDS AND ON NONE OF THE FOUR STATES IT NAMES. NFR-033 (Must, Approved) requires colour contrast for all text on background AND FOR UI COMPONENT STATES - normal, hover, focused, disabled - to meet WCAG 2.2 AA, and states two thresholds explicitly: 4.5:1 for body text, 3:1 for large text and UI components. WHAT EXISTS IS BETTER THAN MOST GATES IN THIS REPOSITORY AND SHOULD NOT BE UNDERSOLD. src/Acmp.Web/src/styles/contrast.test.ts parses tokens.css directly, computes real WCAG relative luminance and contrast ratios, and asserts 20 foreground-on-background token pairs in BOTH the light and the explicit dark palettes - plus a third assertion that the OS-default dark palette inside the prefers-color-scheme media query is IDENTICAL to the explicit one, because they are two hand-maintained copies and only one was reachable by the checks. It also carries its own anti-vacuity guard: before comparing the two dark palettes it asserts the parsed block contains more than ten tokens, so a selector that stopped matching cannot pass by comparing nothing to nothing. THAT GUARD EXISTS BECAUSE THE TEST WAS ONCE FALSELY GREEN in exactly that way - its header records that a plain indexOf matched the selector inside a PROSE COMMENT and returned the LIGHT palette for every dark case, for the file's entire life until 2026-08-10. WHAT IS NOT COVERED, AND IT IS HALF THE REQUIREMENT. Every one of the 20 pairs is asserted at 4.5:1. NOT ONE uses the 3:1 threshold, so the requirement's 'large text and UI components' clause has no case at all - no border-on-background pair, no focus-ring pair, no disabled-state pair. And the four states the requirement names by name - normal, hover, focused, disabled - are absent from the pair table entirely; tokens.css contains only six focus, hover or disabled mentions in total. SCOPE IS NARROWER THAN THE REQUIREMENT TOO: the file's own header says it covers 'the design tokens the Topics screens rely on', not the application. AND THE RENDERED QUESTION IS UNTOUCHED BY DESIGN: color-contrast is explicitly disabled in BOTH axe passes, the jsdom one because there is no layout engine and the live Playwright one by convention, so nothing anywhere measures contrast as actually painted - only as declared in tokens.
