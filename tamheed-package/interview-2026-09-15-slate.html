LL-083 [lessons]

id: LL-083
title: A BACKSLASH-U ESCAPE TYPED INTO A TOOL PARAMETER ARRIVES AS THE RAW CHARACTER, BECAUSE THE PARAMETER IS JSON-DECODED BEFORE THE TOOL SEES IT. FOR AN INVISIBLE OR BIDI-CONTROL CHARACTER THAT PUTS AN UNREADABLE BYTE IN SOURCE: WRITE SUCH ESCAPES WITH A SCRIPT THAT BUILDS THE BACKSLASH FROM ITS CODE POINT, AND GREP FOR THE RAW CHARACTER AFTERWARDS.
statement: THE INSTANCE. `WBS-40.29`, 2026-09-14/15. `lib/bidi.ts` was written with Write and a template holding the U+2068 / U+2069 escapes; the file on disk held the raw FIRST STRONG ISOLATE / POP DIRECTIONAL ISOLATE characters, so the source read as a bare `${s}` in any editor while doing the right thing. The same happened in `bidi.test.ts`, a dashboard test and the Arabic-view spec (all merged in #414), and later in a commit message whose text read 'written as  /  escapes'. Two repair attempts failed the same way: a `node -e` replace whose replacement text passed through three decoders (the parameter's JSON, the shell's double quotes, the JavaScript string) and put the raw character straight back - the script even reported 'escaped 2' per file. What worked: a script with NO backslash in its source, building the escape as String.fromCharCode(92) + 'u2068', then `grep -P` for U+2068/U+2069 returning nothing as the control. Found only because a later grep printed the invisible characters themselves; no gate, lint or test notices a raw isolate (the code is correct either way).
recommendation: (1) Never type a backslash-u escape into a Write/Edit/Bash parameter expecting it to land as six characters; for a character you must name, build it from its code point (String.fromCharCode) in the code you write, or let a script write the escape using String.fromCharCode(92). (2) After writing anything that should contain an invisible, bidi-control or zero-width character, run grep -P for that code point over the files touched - raw is invisible, so only a byte-level check sees it. (3) A tool report of 'replaced N' is not evidence the bytes changed; read the bytes (od -c) or grep for the result. (4) The same applies to commit messages and package text: spell such characters by name (U+2068), not by escape.
rationale: Tool parameters are JSON: a backslash-u there is decoded, the same as in any JSON string. The failure is silent because the raw character is invisible and behaves correctly at run time, so every test passes and a reviewer sees nothing.
kind: improve
category: process
impact_if_followed: Invisible characters never enter source by accident, and a repair is confirmed at the byte level rather than by a script's own count.
impact_if_ignored: Source carries characters no reviewer can see - the next person to edit `${s}` in an isolate template cannot tell it is not a bare interpolation, and a bidi control in the wrong place is a Trojan-Source-shaped hazard.
