Q1 — SoD-4's first half: decision recorder ≠ sole owner/presenter. What strength?

Option A — hard refusal, matching SoD-1 and SoD-3: audit the denied attempt, then 403. Follows C-AUTH-05's summary wording ("enforced as hard authZ checks") literally.

Option B — warn-and-audit, matching SoD-2: recording is allowed, the overlap is flagged on the decision and a distinct audit event is emitted. The pattern already exists and the catalogue already accepts it for one member.

Option C — record SoD-4 as deliberately not enforced in v1, satisfying NFR-064's strength-is-recorded clause without building a guard.

The agent's recommendation is B, and the reasoning against A is the reason the row asks at all. This committee has roughly twenty people and the Secretary drafts decisions as their ordinary job (RecordDecision's own header: "the Secretary (or Chairman) drafts a decision against a topic"). A hard recorder ≠ owner refusal would block a Secretary who also happens to own the topic from recording its decision at all — legitimate minute-taking refused by a control meant to stop self-dealing. B makes the overlap visible and reviewable without making it impossible, which is exactly the trade the catalogue already accepted for SoD-2. ⚠ This is the agent's inference, not a reading of any record: no document states which way SoD-4 should go, which is why the row was written.

⚠ Option C is offered for completeness and is not recommended, because DEC-094 d1 already ruled that the row is settled and then built.

ADR-0010 [adrs]

id: ADR-0010
title: ADR-0010: Always-Attributed Voting Model
context: The committee makes decisions via voting followed by chairman final approval. The voting model must specify: who may vote (eligible voters), what constitutes a quorum, how abstentions are handled, whether votes are attributed to individuals or anonymous, and how the chairman's authority interacts with the vote outcome. Getting this wrong produces either accountability gaps (anonymous votes in a governance body) or a model too complex to implement correctly.
decision: Chosen option: "Always attributed voting — eligible voters, quorum, abstentions, chairman approval/override by name", because accountability is the primary governance requirement: architectural decisions must be traceable to the individuals who made them, and the chairman's authority must be recorded explicitly (not inferred). In v1 there is no anonymity and no ranked-choice — these can be revisited with evidence of a requirement.

### Consequences

- Good: full attribution means the audit log records who voted which way; the chairman's approval or override is a named, timestamped, immutable event; quorum enforcement prevents invalid decisions; abstentions are treated as a deliberate position (not just absence); conflict-of-interest recusals are expressible.
- Bad / trade-off: some committee members may feel attribution inhibits honest voting (the "reluctant dissenter" problem). This is a governance culture decision, not a technical one — the brief mandates attribution, and it is the correct stance for an architecture committee. If anonymous voting is ever required (e.g., for sensitive personnel matters), it must be introduced as a separate vote type with explicit scope, not as a default.

// Segregation-of-duties guards (docs/domain/permission-role-matrix.md §E.4). Pure, side-effect-free predicates the owning
// module's handler calls; a violation is a hard Deny regardless of role. SoD-5 (Administrator
// walled off committee content) is structural — encoded by role lists in the matrix, not here.
public static class SegregationOfDuties
{
    // SoD-1: an action's verifier must be neither its owner nor the assignee who marked it complete.
    // Enforced by the Actions module verify handler (P8); the predicate is proven here in P4.
    public static bool CanVerifyAction(string verifierId, string ownerId, string? completedById) =>
        !string.Equals(verifierId, ownerId, StringComparison.Ordinal) &&
        !string.Equals(verifierId, completedById, StringComparison.Ordinal);

    // SoD-3: the chairman cannot be the sole vote-counter — closing a vote and recording the
    // override on the same decision requires a distinct co-attester (Secretary or a second Member).
    // Enforced by the Vote close / chair-approve handlers (P9); predicate proven here in P4.
    public static bool HasIndependentCoAttestation(string chairmanId, string? coAttesterId) =>
        !string.IsNullOrWhiteSpace(coAttesterId) &&
        !string.Equals(chairmanId, coAttesterId, StringComparison.Ordinal);
}
